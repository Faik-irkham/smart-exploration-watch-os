# Catatan Progres — 23 Juni 2026

Sistem dua-aplikasi pemantauan detak jantung: **watch (Wear OS)** sebagai
peripheral BLE dan **smartphone (Android)** sebagai central, dengan penyimpanan
SQLite dan pola *store-and-forward*.

## 1. Ringkasan

Hari ini sistem berhasil diuji **end-to-end pada dua perangkat fisik** dan
terbukti mengirim data detak jantung dari watch ke ponsel melalui BLE **tanpa
kehilangan data**. Selain itu dilakukan penyempurnaan agar pemantauan tetap
berjalan di latar belakang, perapian arsitektur kode, dan penambahan mekanisme
ekspor data untuk keperluan analisis.

## 3. Hasil verifikasi end-to-end (uji fungsional)

Satu batch berhasil dikirim dan diterima utuh. Metrik per batch terekam otomatis
oleh instrumentasi pada kedua sisi:

| Parameter | Watch (kirim) | Ponsel (terima) |
|-----------|---------------|------------------|
| Jumlah record | 228 | 228 |
| Ukuran payload | 10.717 byte | 10.717 byte |
| Jumlah frame BLE | 24 | 24 |
| MTU hasil negosiasi | 512 | 512 |
| Durasi transfer | 323,1 ms | reassembly 250 ms |
| Throughput | ± 32,4 KB/s | — |
| Simpan ke SQLite | — | 56 ms |

**Delivery ratio batch ini = 228/228 = 100% (tanpa packet/record loss).**

Linimasa koneksi: advertising dimulai → ponsel scan & connect → negosiasi MTU
512 → subscribe karakteristik → batch terkirim & tersimpan. Pencocokan record
dilakukan berdasarkan *timestamp* (`time`, epoch ms) yang dibuat di watch,
sehingga perhitungan tidak bergantung pada sinkronisasi jam antar perangkat.

> Catatan: hasil di atas adalah uji fungsional (satu sesi). Pengukuran formal
> dengan variasi kondisi dan replikasi masih akan dilakukan (lihat bagian 7).

## 4. Perbaikan & pengembangan yang diselesaikan hari ini

1. **Perbaikan protokol penerimaan (reassembly).** Penerima sebelumnya
   memperlakukan tiap notifikasi sebagai satu objek JSON utuh, padahal pengirim
   memecah batch menjadi beberapa *frame* ber-opcode (START/DATA/END). Penerima
   diperbaiki agar merangkai frame dengan benar lalu mem-parsing JSON array.
2. **Instrumentasi metrik.** Kedua aplikasi kini mencatat metrik per batch
   (jumlah record, byte, frame, MTU, durasi transfer, throughput, waktu
   reassembly & simpan) dengan penanda log `HR-METRIC` yang dapat ditarik dan
   diolah untuk tabel hasil.
3. **Eksekusi latar belakang (foreground service).** Ditambahkan *foreground
   service* + *wake lock* di kedua aplikasi sehingga perekaman dan pengiriman/
   penerimaan tetap berjalan saat aplikasi di-*background* atau layar mati.
4. **Perapian arsitektur kode (state management BLoC).** Logika dipisahkan dari
   antarmuka menggunakan pola BLoC/Cubit dan dipecah per fungsi (model, data,
   BLE, state, UI, widget). Sisi native (Kotlin) juga dipecah per kelas.
   Perubahan bersifat menjaga fungsi (tidak mengubah perilaku).
5. **Fitur ekspor data.** Kedua aplikasi dapat mengekspor isi basis data ke
   folder Downloads dalam format **CSV** dan **berkas .db**, sehingga data dapat
   ditarik tanpa akses root untuk dianalisis.
6. **Skrip bantu pengambilan data** dibuat untuk menarik berkas ekspor dari
   kedua perangkat dan menghitung delivery ratio secara otomatis.

## 5. Validitas & verifikasi teknis

- Analisis statis (`flutter analyze`) bersih pada kedua proyek.
- Kompilasi kode native (Kotlin) sukses pada kedua proyek.
- Verifikasi end-to-end dilakukan di perangkat fisik (BLE tidak dapat
  diemulasikan).

## 6. Catatan & keterbatasan

- Cakupan eksekusi latar belakang: *background* + layar mati. Skenario aplikasi
  ditutup paksa / setelah *reboot* belum termasuk (keterbatasan OEM/Wear OS).
- Pada perangkat dengan manajemen baterai agresif (mis. MIUI), pengecualian
  optimasi baterai disarankan agar proses tidak dihentikan sistem.

## 7. Rencana berikutnya

1. Pengukuran formal dengan variasi: interval pengiriman (3 vs 5 menit), jarak
   watch–ponsel, dan skenario gangguan koneksi.
2. Replikasi tiap kondisi (≥ 3–5 kali) untuk memperoleh rata-rata ± simpangan
   baku.
3. Analisis: delivery ratio, latensi transfer, throughput, dan konsumsi daya.
4. Penyusunan tabel & grafik hasil untuk naskah.
